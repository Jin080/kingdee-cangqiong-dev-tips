# 星瀚元数据使用说明

## 作用边界

**只在编写插件代码时使用**，不参与普通问答检索。

适用场景：
- 用户要求编写星瀚表单插件、操作插件、服务端插件
- 用户要求确认某个页面/单据/列表的表单标识（fnumber）
- 用户要求确认字段标识、按钮标识、单据体标识、列表列标识
- 用户给出业务页面名称，需要确认 BOS 元数据里的 key

不适用场景（走 reading-guide.md 的帮助中心链路）：
- 功能介绍
- 菜单操作步骤
- 报错排查
- 产品配置说明

---

## 元数据索引文件

先读 `references/config.md` 获取 `BASE_PATH`。元数据索引使用：

```
{BASE_PATH}\星瀚元数据-index.jsonl
```

这是星瀚插件开发的内部辅助层，不是独立问答入口。

若该文件不存在，说明当前机器尚未安装星瀚元数据索引；应提示用户先补装对应语料/元数据包，不要回退读取原始导出文件。

每行对应一个表单，格式：

```json
{
  "fnumber": "表单标识",
  "name": "表单名称（中文）",
  "model_type": "模型类型",
  "fields": [{"key": "字段标识", "name": "字段名称"}],
  "buttons": [{"key": "按钮标识", "name": "按钮名称", "op": "操作key（可选）"}],
  "entries": [{"key": "单据体标识", "name": "单据体名称"}],
  "list_columns": [{"key": "列标识", "name": "列名称", "field_id": "绑定字段id"}],
  "plugins": ["已注册插件类名1", "已注册插件类名2"]
}
```

## 检索步骤

### 第一步：定位表单

用 Grep 工具在索引文件中搜索用户提到的业务名称或标识：

- 按中文名称搜索（如"采购订单"）→ 匹配 `name` 字段
- 按表单标识搜索（如"pur_order"）→ 匹配 `fnumber` 字段

若多条命中，根据用户描述的业务场景（单据/列表/基础资料）选最匹配的一条。

若无命中，明确告知用户："未在元数据中找到该表单，请确认业务对象名称是否正确。"

### 第二步：提取开发所需标识

从命中行中按需取出：

| 开发需求 | 取哪个字段 |
|---------|-----------|
| 注册插件时的表单标识 | `fnumber` |
| 字段取值 / 赋值 | `fields[].key` |
| 按钮点击事件 | `buttons[].key` |
| 单据体操作 | `entries[].key` |
| 列表列定位 | `list_columns[].key` 或 `.field_id` |
| 参考现有插件实现 | `plugins[]` |

### 第三步：输出给用户

只输出本次开发真正需要的标识，不要整条 JSON 全部贴出。

推荐格式：
```
表单标识：{fnumber}
目标字段：{key}（{name}）
相关按钮：{key}（{name}）
单据体：{key}（{name}）
```

确认标识后，若还需要 BOS 接口、事件、生命周期机制，再按需参考苍穹官方开发文档；必要时可结合 `kingdee-cangqiong-dev-tips` 组织代码。

---

## 禁止行为

- 不要因为索引缺失就回退读取原始 800MB 导出文件
- 不要猜测标识（索引未命中就明确说未找到）
- 不要把所有字段一次性全部输出
- 不要在用户只是询问功能/操作时读取元数据
- 不要因为需要参考苍穹机制，就把整个问题改判为纯苍穹问题
