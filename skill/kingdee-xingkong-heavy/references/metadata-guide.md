# 星空元数据使用说明

## 作用边界

**只在编写插件代码时使用**，不参与普通问答检索。

适用场景：
- 用户要求编写星空表单插件、操作插件、服务端插件
- 用户要求确认某个页面/单据/列表的表单标识（form_id）
- 用户要求确认字段标识、按钮标识、单据体标识
- 用户要求区分字段 `Key`、`PropertyName`、`FieldName`
- 用户给出业务页面名称，需要确认 BOS 元数据里的 key

不适用场景（走 reading-guide.md 的帮助中心链路）：
- 功能介绍
- 菜单操作步骤
- 报错排查
- 产品配置说明

## 元数据索引文件

先读 `references/config.md` 获取 `BASE_PATH`。元数据索引使用：

```
{BASE_PATH}\星空元数据-index.jsonl
```

这是星空插件开发的内部辅助层，不是独立问答入口。

若该文件不存在，说明当前机器尚未安装星空元数据索引；应提示用户先补装对应语料/元数据包，不要回退读取原始导出文件。

每行对应一个表单，格式：

```json
{
  "form_id": "表单标识（如 STK_TRANSFERIN）",
  "model_type": "模型类型（如 BOS_BillModel / BOS_BaseDataModel）",
  "fields": [{
    "key": "字段唯一标识（view / 控件层）",
    "name": "字段名称",
    "property_name": "ORM / model 实体属性",
    "field_name": "数据库字段名或底层字段名",
    "entity_key": "所属单据体标识（有则返回）"
  }],
  "buttons": [{"key": "按钮标识", "name": "按钮名称"}],
  "entries": [{"key": "单据体标识", "name": "单据体名称"}],
  "plugins": ["已注册插件类名1", "已注册插件类名2"]
}
```

**注意**：索引中没有 `list_columns`（列表列）；如需列标识，搜索字段的 `key`。

## 检索步骤

### 第一步：定位表单

用 Grep 工具在索引文件中搜索用户提到的业务名称或标识：

- 按表单标识搜索（如"STK_TRANSFERIN"）→ 匹配 `form_id` 字段
- 按字段/插件中的关键词搜索 → 匹配相关行

若多条命中，根据用户描述的业务场景（BOS_BillModel=单据、BOS_BaseDataModel=基础资料）选最匹配的一条。

若无命中，明确告知用户："未在元数据中找到该表单，请确认业务对象标识是否正确。"

### 第二步：提取开发所需标识

从命中行中按需取出：

| 开发需求 | 取哪个字段 |
|---------|-----------|
| 注册插件时的表单标识 | `form_id` |
| 控件事件、updateView、前端字段定位 | `fields[].key` |
| 元数据取数、DynamicObject / model 属性定位 | `fields[].property_name` |
| 数据库字段排查、底层字段映射 | `fields[].field_name` |
| 按钮点击事件 | `buttons[].key` |
| 单据体操作 | `entries[].key` |
| 参考现有插件实现 | `plugins[]` |

### 第三步：输出给用户

只输出本次开发真正需要的标识，不要整条 JSON 全部贴出。

推荐格式：
```
表单标识：{form_id}
目标字段：{key}（{name}）
实体属性：{property_name}
数据库字段：{field_name}
相关按钮：{key}（{name}）
单据体：{key}（{name}）
```

确认标识后，若还需要 BOS 接口、事件、生命周期机制，再按需参考苍穹官方开发文档；必要时可结合 `kingdee-cangqiong-dev-tips` 组织代码。

## 禁止行为

- 不要因为索引缺失就回退读取原始 167MB 导出文件
- 不要猜测标识（索引未命中就明确说未找到）
- 不要把所有字段一次性全部输出
- 不要在用户只是询问功能/操作时读取元数据
- 不要因为需要参考苍穹机制，就把整个问题改判为纯苍穹问题
