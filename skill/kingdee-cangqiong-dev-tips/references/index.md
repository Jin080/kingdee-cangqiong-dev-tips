# 金蝶苍穹 Skill 路由索引

这份索引只负责两件事：

1. 把问题或投稿路由到最相关的主题文件
2. 控制读取范围，避免每次都全量读取所有参考文档

## 渐进式披露规则

固定读取顺序：

1. 先读本索引
2. 再读 1 个最相关主题文件
3. 只有跨主题时，才补读第 2 个主题文件

禁止默认行为：

- 不要先把 `pages.md`、`interaction.md`、`backend-data.md`、`operations.md` 全部读一遍
- 不要因为一个投稿里出现多个关键词，就机械加载全部文档

## 一级路由：按运行位置和动作分

### `pages.md`

适用问题：

- 表单页面字段取值
- 页面字段赋值
- 基础资料属性取值
- 单据体/子单据体取值与赋值
- 列表页面选中行、列表字段
- 页面参数、View 状态控制

优先关键词：

- `getModel`
- `getValue`
- `setValue`
- `单据体`
- `子单据体`
- `列表`
- `选中行`
- `页面参数`

### `interaction.md`

适用问题：

- 值更新事件
- 用户点击事件
- 父子页面通信
- F7 选择界面
- 前后端交互
- 代码赋值后是否触发联动

优先关键词：

- `propertyChanged`
- `beginInit`
- `endInit`
- `click`
- `itemClick`
- `父子页面`
- `F7`
- `过滤`

### `backend-data.md`

适用问题：

- 新建数据对象
- 保存、查询、删除数据对象
- DynamicObject 处理
- ORM 查询
- 过滤条件

优先关键词：

- `DynamicObject`
- `DynamicObjectCollection`
- `QueryServiceHelper`
- `BusinessDataServiceHelper`
- `SaveServiceHelper`
- `QFilter`
- `ORM`

### `operations.md`

适用问题：

- 代码触发提交/审核/保存等操作
- 操作后刷新界面
- 操作后提示
- 界面插件与操作插件传参

优先关键词：

- `invokeOperation`
- `OperationServiceHelper`
- `afterDoOperation`
- `updateView`
- `操作插件`
- `提示`
- `传参`

## 二级路由：按投稿内容分

### 页面类投稿

特征：

- 主要讨论字段值怎么取、怎么写
- 主要风险在字段标识、行号、基础资料属性、单据体层级

默认归档：

- `references/pages.md`

### 交互类投稿

特征：

- 主要讨论事件触发、联动、按钮点击、父子页面、F7
- 主要风险在事件时机、监听器注册、前后端边界

默认归档：

- `references/interaction.md`

### 后端数据类投稿

特征：

- 主要讨论对象构造、保存、查询、过滤、删除
- 主要风险在对象类型、元数据、过滤条件、空值处理

默认归档：

- `references/backend-data.md`

### 操作类投稿

特征：

- 主要讨论代码触发操作、操作结果、刷新、提示、插件传参
- 主要风险在运行上下文、操作编码、结果判断

默认归档：

- `references/operations.md`

## 拆分规则

为了让 skill 越来越大但仍然可查，不要无条件新增文件。

优先级：

1. 先并入现有主题文件的已有小节
2. 没有合适小节时，新增二级或三级标题
3. 只有当某个主题文件持续膨胀到难以检索时，才拆新文件

建议阈值：

- 单个主题文件超过约 `900` 行，且新增内容已形成稳定子主题
- 同一稳定子主题累计至少 `3` 次可复用投稿

拆分后要求：

- 必须先更新本索引，再新增正文文件
- 索引里明确写清楚“什么问题读什么文件”

## 索引维护规则

每次把投稿正式整合进 skill 时，都要检查：

1. 主题归类是否准确
2. 新增关键词是否需要补进本索引
3. 现有小节标题是否还能支撑后续检索
4. 是否出现“一个问题要反复读多个文件”的迹象

如果第 4 条已经频繁出现，说明索引粒度不够，需要细化。
